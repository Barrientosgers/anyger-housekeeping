# Security review (Phase 6)

A final review of the whole application before the repository is made public. It combined automated scanning, a read of the code against the OWASP Top 10, black-box probing of the **live** site, and regression tests. This page records what was checked, what was **found and fixed**, and what is knowingly left open.

Reviewed commit range: Phases 1-5 (`main` at `293a400`) plus the fixes below.

## Controls checked and found sound

Each is pinned by a test, the probe, or both.

- **Authentication:** all 12 private routes return 401 when logged out; the only open routes are the booking form, login, and `/healthz`.
- **Sessions:** a new session id on every login (no fixation); logout destroys the server-side session so the old cookie stops working; the cookie is `HttpOnly`, `SameSite=Lax`, `Secure` in production behind HTTPS, and expires in 90 days.
- **CSRF and cross-origin:** state-changing requests need a custom header; no CORS grant is ever sent, including for preflights.
- **Injection:** SQL-injection strings in bodies, query strings, and path segments are stored as text or rejected with 400/404 and never reach the database; prototype-pollution payloads change nothing; unexpected fields (`status`, `role`, `created_by`, `id`) are ignored (no mass assignment).
- **Output:** markup in notes, names, and translations is rendered as text (component tests).
- **Errors:** a deliberately failing database yields a bare `{"error":{"code":"internal"}}` with no message, query, or stack; unknown paths give a bare JSON 404.
- **Static hosting:** six path-traversal and sensitive-file probes against the live site (`/..%2f..%2fetc/passwd`, `/.env`, `/.git/config`, and others) returned nothing.
- **Transport:** HTTP redirects to HTTPS; HSTS set; no `X-Powered-By`.
- **Secrets:** environment variables only; misconfiguration stops the server at startup and names the setting, never its value.
- **Container:** runs as a non-root user; CI token is read-only.

## Not fixed on purpose (accepted risks)

Listed in full in [SECURITY.md](../SECURITY.md) under "Known gaps". In short: one shared login with no second factor; in-memory rate limits (fine for a single instance); no CAPTCHA (the next step if real spam appears); texts and translations pass through third parties (mitigated by generic texts and note-only translation); free-tier hosting has no uptime or backup guarantees; machine translation is less accurate than a large model.
